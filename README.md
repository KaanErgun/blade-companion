# Blade Companion

An unofficial Android companion for a personal Vuzix Blade OS project, by **Kaan Ergün**. Open source under the [MIT license](LICENSE). This project is not affiliated with or endorsed by Vuzix.

The current version is `1.0.0-rc-beta-dev`, a local development package. It is not a published release.

## Current scope

The native Android app has Device, Connection, Market and About screens, with Turkish UI strings in Android resources. Device now provides the paired local camera and remote-assistance flow: explicit five- or thirty-minute start, stop, live 640×480 JPEG preview, freeze/resume, short UTF-8 instructions, normalized arrow gestures, and SHA256-verified photo export through Android's document picker.

Connection imports the owner's protocol-v1 pairing JSON through an explicit document selection. It stores credentials encrypted with an Android Keystore AES-GCM key, allows a canonical private/link-local IPv4 endpoint, and provides connect, disconnect and local pairing removal. The endpoint can use USB networking or a reachable LAN bridge. Two direct TLS 1.2/1.3 sockets carry control and subscribed frames; the exact SHA256 of the leaf certificate's DER is verified before AUTH. There is no proxy, DNS endpoint, certificate fallback, automatic reconnect, or automatic camera start. The control channel sends a PING every five seconds. Backgrounding closes both raw sockets immediately; TLS teardown runs off the UI thread, and the server owns the camera shutdown and lost-link lease. Only a visible STARTING/ACTIVE session keeps the screen awake. The optional aggregate report separates received frames, successful JPEG decodes and unique new frames submitted to the preview View. Decode and preview FPS use their own first/last event spans; these are not physical display or optical latency measurements. The latest completed report is saved in app-private storage and can be explicitly exported through SAF after the session ends. Reports contain counts, byte totals, spans, rates and an end reason, with no image, frame/session identity, endpoint or credential.

Annotations target only the displayed, successfully frozen session/frame. Letterbox touches are rejected and arrows are normalized to the uncropped image. New frame IDs must increase as unsigned 64-bit values; foreign, malformed and late-session frames are rejected. Photos are checked against the server's SHA256 and are exported from separate private cache files, including document-picker recreation. Import/removal revisions prevent an older pending credential write from restoring a forgotten pairing.

The separate USB diagnostics still discover real USB host devices, request Android permission only after a user action, and issue the project's fixed read-only kernel information request.

Discovery and permission are displayed separately from a verified kernel response. Discovery accepts three narrow USB 2 layouts: VID:PID `0525:a4a7` with one ACM control/data pair, and `1d6b:0104` with device class/subclass/protocol `ef/02/01`, either ECM or NCM interfaces 0/1, and ACM interfaces 2/3. Both network layouts require an empty data alternate 0 and bulk alternate 1; the five descriptor records represent four interface IDs. ECM uses control `2/6/0` and data `10/0/0`; NCM uses control `2/13/0` and data `10/0/1` on both alternates. After Android permission, raw configuration lengths/values, required interface association descriptors (IADs), CDC union ownership/pairing and endpoint layout are checked before either ACM interface is claimed. NCM additionally requires the Linux NCM 1.00 functional descriptor with capabilities `0x11`. The raw network type must match the selected discovery profile. Network interfaces remain unclaimed. These checks identify a supported layout, not an authenticated device. Each request uses a fresh response token, a bounded response and a timeout. It sends `uname -srm` with fixed framing; there is no arbitrary command entry, reboot or firmware write action. The USB response is shown in memory and is not logged or uploaded.

Market now imports a **separate owner-management pairing record** (`kind: blade-app-management`) into a separate Android Keystore alias and encrypted preferences. The camera's five-field pairing remains unchanged. If both records exist, their certificate pins must match and their tokens must differ. The native screen lists installed applications and enabled/running state, imports a `.bladeapp` through Android's document picker, and streams a private on-disk snapshot in bounded 64 KiB chunks (64 MiB package limit). The snapshot is unlinked while its descriptors remain open, including upload cancellation/process-death cleanup.

Only the Blade's verified preview supplies package ID/version/signer/permissions. Installation or update requires explicit permission confirmation; only bounded HUD text, network and app-private storage grants are offered. Root, camera and microphone packages cannot be installed through this normal-app path. HUD apps display an instruction to open them from the glasses' Uygulamalar menu; the phone does not launch a HUD session. The server's 15-second post-verification idle deadline is shown as a countdown; expiration closes the upload and requires a new explicit file selection. There is no automatic upload or mutation retry. Enable, disable, launch, and removal with an explicit keep/delete-data choice use the displayed package revision as a compare-and-swap precondition. Updates enable but do not launch; disable/update/remove stop the app through the OS. Backgrounding closes management transport and pending uploads, without stopping installed apps. A private app-ID/operation marker survives uncertain mutation responses and recreation; the user queries STATUS before starting another mutation.

Signed catalog source support imports an explicitly selected Ed25519 publisher key and the SDK canonical signed catalog through SAF or HTTPS. Revision high-water marks prevent rollback and replacement at the same revision. A selected entry can download over HTTPS or select its package through SAF for offline distribution. Both paths enforce the signed size/hash and bind the OS-verified preview to the selected catalog entry before explicit installation. Platform Ed25519 support is required for catalog functions; unsupported Android providers show an explicit message. The APK has no added runtime dependency. Catalog import, offline selection and download/install UI acceptance remain pending. Device updates, network trust-key provisioning, root grants and rollback UI remain outside this implementation slice. Product messages use the fixed BLD1 binary protocol, never USB shell commands or an assumed HTTP API. Paired camera/assistance has initial real phone evidence below; market mutations and complete lifecycle acceptance remain pending.

## Local build

Prerequisites: JDK 17, Android SDK Platform 35, Build Tools 34.0.0, Gradle 8.9 and Android Gradle Plugin 8.7.3. The wrapper verifies the Gradle distribution checksum. There are no runtime dependencies beyond Android platform APIs. Minimum Android API: 23; target: 35.

Set `JAVA_HOME` to a JDK 17 installation. Put the Android SDK path in ignored `local.properties`:

```properties
sdk.dir=/absolute/path/to/Android/sdk
```

Then run the canonical offline gate:

```sh
./scripts/check.sh
```

The Gradle distribution and build plugin must already be cached for offline use. For an initial connected setup, run `./gradlew --no-daemon :check` once. The gate compiles the Android code, runs Android lint, executes Android-free tests for USB profile selection, camera/management framing, bounded package transfer, local session lifecycle and frame coordinates, then builds `app/build/outputs/apk/debug/app-debug.apk`. It also rejects hosted CI configuration and Android imports in the core package. Hardware transport and visual UI checks are separate from this gate.

Build outputs, local SDK configuration, device evidence and local artifacts are ignored. Nothing in the gate installs an APK or changes a connected device.

## USB behavior

Connect a data-capable USB cable with the phone acting as host and the Blade running the project's USB diagnostic image. Open **Bağlantı**, refresh the actual device list and grant permission to the matching diagnostic device. **Kernel bilgisini oku** runs the bounded probe. A matching descriptor alone is not a device identity or a successful connection.

This uses Android's [USB host APIs](https://developer.android.com/develop/connectivity/usb/host). USB permission is temporary and expires on detach. The application requests normal Internet and network-state permissions for the paired local TLS transport. It does not request phone camera, microphone, or broad storage access; file import/export uses explicit Android document selection.
